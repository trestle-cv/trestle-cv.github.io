Health and operations

The first runnable server exposes small system endpoints and structured request logs without application data.

Endpoints

PathPurposeSuccess
/system/healthProcess liveness{"status":"ok"}
/system/readyTraffic readiness{"status":"ready"}
/system/versionBuild and platform identityVersion, commit, date, Go, OS and architecture

Readiness semantics

A process may be healthy while returning 503 not_ready. CP02 will connect readiness to database initialization and migrations. Every response receives an X-Request-ID suitable for correlation.

Logs

Requests are emitted as structured JSON with method, path, request ID and duration. Headers, query values and credentials are not logged.

Pre-release boundary

These contracts exist in source and tests, but no supported release archive is available.
