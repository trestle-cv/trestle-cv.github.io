Architecture

Single-node clarity first.

The initial topology is one Go process owning one SQLite database and serving an embedded Nift-built administration interface.

clients → HTTP / JSON / SSE → Trestle → transactions → SQLite
                                  ↳ files → local / S3
                                  ↳ jobs → webhook / Lambda

Transaction rule

A state change, durable event, audit fact and required outbox job are written in one SQLite transaction. Workers act only after commit.

Authority boundaries

Application, administration and system APIs have distinct authority. Trusted backends use scoped service accounts; ordinary application traffic never needs a superuser credential.

Scaling boundary

The first consistency model assumes one process owns writes, jobs and event ordering. Multi-node operation would require a new explicit contract rather than a shared-filesystem switch.
