CP02 · Implemented

SQLite foundation

Trestle starts with one process owning one SQLite database at <data-dir>/trestle.db.

Startup contract

  • The data directory is created with owner-only permissions.
  • Foreign keys are enabled and verified before readiness.
  • A finite five-second busy timeout avoids unbounded lock waits.
  • WAL mode is requested for the supported local-filesystem deployment.
  • The process refuses a database from a newer Trestle schema version.

Connection ownership

The initial store serializes access through one database connection. That keeps migration and transaction behavior deterministic while the product remains explicitly single-node.

Filesystem boundary

Network filesystems and multiple Trestle processes sharing the same database are not supported. Backup and restore guarantees arrive at CP20.
