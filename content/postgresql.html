PostgreSQL system schema

Trestle maps one logical 13-version schema to reviewed PostgreSQL DDL while preserving the external HTTP contract.

Migration ownership

A PostgreSQL advisory lock serializes migration startup. Trestle reads the maximum recorded logical migration, refuses a future version and applies each remaining version in its own transaction. Failed DDL and its migration record roll back together.

Readiness

The service does not become ready until the connection succeeds, migrations finish and the database identity marker matches postgres. Connection failures are bounded by the configured startup timeout.

Current limit

This checkpoint proves the Trestle system schema. Dynamic collection tables and provider-level feature parity arrive in PG05 onward, so PostgreSQL is still experimental.
