CP04 - Implemented

First-run administration

A fresh Trestle database opens one race-safe setup path for creating its first administrator. There is no default password or permanent setup credential.

Bootstrap flow

  1. Start Trestle on its default loopback address.
  2. Open the dashboard from the same machine or through a correctly configured HTTPS proxy.
  3. Enter a valid email and a password of at least 7 characters.
  4. Trestle hashes the password with Argon2id and commits the administrator.
  5. The setup path closes immediately and returns a rotated server-side session.

Race behavior

Setup checks and insertion occur inside one database transaction, and competing requests create exactly one administrator on both providers. SQLite serializes through its single owned connection; PostgreSQL takes a transaction-scoped advisory lock so READ COMMITTED count-then-insert cannot double-win. Losers receive a stable 409 setup_complete response.

Interrupted setup

A crash after provider selection but before an administrator is committed leaves a resumable incomplete setup: on restart the provider connection is re-established, validated migration history is read, and administrator creation remains available. Once an administrator commits, setup never reopens.

Exposure boundary

Complete setup over loopback or reviewed HTTPS. When a reverse proxy is used, bind Trestle privately, configure the exact trusted proxy CIDR, preserve Host and replace forwarded headers at the edge.
