Security

Design commitments are not shipped guarantees.

This page records the intended trust model. Trestle will claim controls only when implementation and adversarial tests exist.

Separate identities

Application users, service accounts, personal tokens, function grants and superusers remain distinct in storage, token audience, middleware, audit and UI.

Rules everywhere

Collection policy must cover list, lookup, relations, batches, files and realtime. Filters and rules are parsed into typed ASTs and compiled to parameterized queries.

Required evidence

The programme includes enumeration, fixation, CSRF, scope confusion, injection, traversal, replay, slow-consumer, SSRF, migration and restore testing before stable release.

Not production ready

The repository is currently a scaffold and must not be exposed as an application service.
