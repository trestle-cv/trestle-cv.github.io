Deployment

Install Trestle

Two verified download paths: install on this user account, or download a verified executable into the current directory. Both fetch the exact release archive and its SHA256SUMS, verify the archive before writing anything, and never execute the downloaded binary.

Install on this user account

curl -fsSL https://trestle.cv/install.sh | sh
~/.local/bin/trestle version

The installer writes only to ~/.local/bin by default and does not use root. If that directory is not on PATH, it prints the path you need to add.

Download into this directory

mkdir my-trestle
cd my-trestle
curl -fsSL https://trestle.cv/download.sh | sh
./trestle

download.sh writes only ./trestle in the current directory and changes nothing else. It is suitable for portable folders, testing, servers managed manually, and anyone who wants to inspect exactly where the binary lives. It never touches PATH, shell startup files, ~/.local/bin, /usr/local/bin, configuration, services or Trestle data.

Pin a release

curl -fsSL https://trestle.cv/download.sh | sh -s -- --version v0.1.0
curl -fsSL https://trestle.cv/download.sh | sh -s -- --output ./some-name

download.sh refuses to overwrite an existing file, directory or symlink; pass --force to replace it. Pinned installs work the same way with install.sh.

Prerelease builds

curl -fsSL https://trestle.cv/download.sh | sh -s -- --version v0.1.0-rc.1
curl -fsSL https://trestle.cv/install.sh | sh -s -- --version v0.1.0-rc.1

Pre-release builds must be selected explicitly by version. The unversioned latest commands intentionally ignore prereleases, so curl ... | sh without --version will not fetch one. Normally use the stable command once a stable release exists; pin a prerelease only when you specifically want to test an upcoming release.

System-wide install

curl -fsSL https://trestle.cv/install.sh | sudo sh -s -- --system
/usr/local/bin/trestle version

--system is explicit and requires root. Running the ordinary per-user mode as root is refused. Do not describe download.sh as installation; it only places a verified executable in the current directory.

Verified by default

Install, download and update all verify the selected archive against the release SHA256SUMS (with sha256sum, falling back to shasum -a 256 on macOS) and fail closed when the checksum file is unavailable, the archive has no exact entry, the entry is malformed, or the archive is corrupted.
