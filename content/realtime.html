Durable realtime

Every committed record mutation writes a monotonically sequenced event in the same SQLite transaction and can be consumed through Server-Sent Events.

Connect

const events = new EventSource("/api/v1/realtime");
events.addEventListener("record.created", event => {
  console.log(JSON.parse(event.data));
});

The stream requires an authorized administrator session or a credential with records:read. Optional ?topic=record.updated filtering happens server-side.

Reconnect and replay

Browsers automatically send Last-Event-ID after a disconnect. Trestle resumes after that durable sequence. Fifteen-second comment heartbeats keep well-configured proxies from idling the connection.

Operational boundaries

Each poll reads at most 100 events, the dashboard retains only its latest 200 rendered entries, and disconnect cancellation immediately stops the loop. Reverse proxies must disable response buffering for this endpoint.
