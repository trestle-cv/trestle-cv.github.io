Examples · real product paths

Dogfood applications

These are separate, runnable applications built against Trestle's published HTTP contracts. They make different architectural choices and expose different parts of the platform to realistic use.

User-facing workflow

Incident Desk

An incident-management workspace with application users, rotating sessions, ownership rules, typed records, live updates and record-bound attachments.

  • Browser authentication and refresh rotation
  • User-aware list, create, update and delete rules
  • SSE replay and authenticated file delivery
  • SQLite and PostgreSQL smoke paths

High-volume service workflow

Signal Forge

An observability explorer that imports synthetic operational events in 1,000-record transactions, then filters and paginates them through a scoped service credential.

  • Deterministic 10k, 100k and 1m event seeding
  • Typed telemetry, services, hosts and deployments
  • Bounded server-side filters and cursor pagination
  • No direct SQLite access from the application
signal-forge bootstrap
signal-forge seed events 1000000

Why two examples?

Incident Desk tests identity-heavy collaboration. Signal Forge tests trusted-service access and sustained batch ingestion. Together they show that Trestle is a backend boundary rather than a prescribed frontend framework or application architecture.

Reproducible, not preloaded

Neither repository commits generated application data. Run each bootstrap and seed path against a disposable Trestle data directory to reproduce the exercise.
