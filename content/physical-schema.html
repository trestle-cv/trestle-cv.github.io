CP06 · Implemented

Physical collection schema

Every base collection receives its own SQLite STRICT table.

Generated record columns

Every table includes stable record ID, positive version, created time and updated time columns. Field columns use stable hashed identifiers. Text-like, date, select and relation metadata map to text storage; numbers map to real values; booleans are constrained integers; JSON is checked with SQLite's JSON validator.

Constraints

Required and unique metadata becomes physical NOT NULL and UNIQUE constraints. Application validation will provide friendlier errors at CP07, while SQLite remains the final integrity boundary.

Deletion

Deleting a collection drops its physical table and metadata in one transaction. This is intentionally irreversible until backup/restore support lands.

Relations

Relation values have physical storage, but target-aware record validation and referential integrity become active with record CRUD in CP07.
