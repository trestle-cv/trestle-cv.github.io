The release-candidate programme is complete.

Trestle was delivered as ordered vertical checkpoints, each with implementation, dashboard UX, public documentation and verification. A separate PostgreSQL parity campaign is underway; it is not part of the current available contract.

Release candidate

PG00 complete; PG01-11 planned

PostgreSQL parity

The SQL surface and behavioral parity corpus are now classified. The remaining campaign adds secure configuration, dual migrations, collections, records, identity, files, automation, recovery and offline database migration behind the same HTTP contracts.

SQLite remains the available database

The current release candidate supports one Trestle process owning one SQLite database on a local filesystem. PostgreSQL work is not an availability claim until the whole parity matrix passes.

No stable version is published yet. Completion of a roadmap is evidence, not immunity from defects.
