Distribution

Six verified release archives.

Every tagged release produces self-contained archives with the Nift dashboard embedded in the Trestle binary.

Verified by default

install.sh, download.sh and update.sh each verify the selected archive against the release SHA256SUMS before extracting it and fail closed on a missing checksum file, a missing exact entry, a malformed entry or a corrupted archive. The checksum tool is sha256sum with a shasum -a 256 fallback on macOS.

Download into this directory

curl -fsSL https://trestle.cv/download.sh | sh
./trestle version

Prerelease builds

curl -fsSL https://trestle.cv/download.sh | sh -s -- --version v0.1.0-rc.1

Prereleases (vX.Y.Z-*) are published as GitHub prereleases and must be selected explicitly by version; the unversioned latest commands select the stable v0.1.2 release and intentionally ignore prereleases.

For direct verification of a manually downloaded archive:

sha256sum -c SHA256SUMS
./trestle version

The version command reports the injected version, source commit, build date, Go version, operating system and architecture. Release automation also publishes build provenance for the generated artifacts.

Archive contract

Each archive contains the executable, README and license beneath one versioned directory. Runtime assets are embedded; Nift, Node and Go are not deployment dependencies.

Release-candidate matrix

CP23 rebuilds all six archives, verifies their checksums and layout, executes the Linux amd64 artifact, runs user installation, update and rollback drills, and starts a clean instance from source-built output. The v0.1.0-rc.1 clean-machine release rehearsal passed on a fresh GitHub-hosted runner: every checksum verified, build provenance verified for all six archives against the pinned release workflow, and the public download, install and first-run paths exercised end-to-end.
