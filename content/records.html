Records

Versioned records are stored in each collection's typed physical table and exposed through plain HTTP. The same request and response envelopes work with browser fetch, server runtimes and generated clients.

Dashboard editor

Open a collection and choose New record. Trestle opens a syntax-highlighted JSON editor prefilled with every field from the collection schema. Editing a row opens the same editor with the complete current values, so a user never starts from an unexplained empty object. Records are fetched in bounded cursor pages without leaving the dashboard, and page checkboxes support version-safe bulk deletion.

Endpoints

GET    /api/v1/collections/:collection/records
POST   /api/v1/collections/:collection/records
GET    /api/v1/collections/:collection/records/:id
PATCH  /api/v1/collections/:collection/records/:id
DELETE /api/v1/collections/:collection/records/:id

Each response includes a stable ID, positive version, created and updated timestamps, and a values object. Use ?fields=title,status for value projection and ?limit=1..100 for bounded lists.

A small fetch client

Centralize authorization, JSON decoding and Trestle's error envelope once. The token can be an application-user access token in a browser or a scoped service token in trusted server code.

const baseURL = location.origin;

async function trestle(path, options = {}) {
  const response = await fetch(new URL(path, baseURL), {
    ...options,
    headers: {
      Accept: "application/json",
      Authorization: `Bearer ${accessToken}`,
      ...options.headers,
    },
  });

  const body = response.status === 204 ? null : await response.json();
  if (!response.ok) {
    const error = new Error(body?.error?.message ?? "Trestle request failed");
    error.code = body?.error?.code;
    error.requestId = body?.error?.requestId;
    throw error;
  }
  return body;
}

This browser example assumes your reverse proxy serves the application and Trestle API from one origin. In server-side JavaScript, replace location.origin with a private Trestle URL from configuration. Preserve the machine-readable error code and request ID so the UI can handle expected failures and an operator can trace unexpected ones.

Create and read a record

const created = await trestle(
  "/api/v1/collections/issues/records",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Idempotency-Key": crypto.randomUUID(),
    },
    body: JSON.stringify({
      values: { title: "Investigate latency", priority: 2 },
    }),
  },
);

const issue = await trestle(
  `/api/v1/collections/issues/records/${encodeURIComponent(created.id)}`,
);

console.log(issue.id, issue.version, issue.values.title);

The idempotency key makes a retried create safe after a network interruption. Record IDs must still be encoded before being inserted into a URL path.

Update with optimistic concurrency

const updated = await trestle(
  `/api/v1/collections/issues/records/${encodeURIComponent(issue.id)}`,
  {
    method: "PATCH",
    headers: {
      "Content-Type": "application/json",
      "If-Match": `"${issue.version}"`,
    },
    body: JSON.stringify({ values: { priority: 1 } }),
  },
);

If-Match prevents an older screen from silently overwriting a newer edit. If another request already changed the record, Trestle returns 412 version_conflict; reload the current record and ask the user how to reconcile it.

Filter and follow cursor pages

async function* issuePages() {
  let cursor = "";

  do {
    const query = new URLSearchParams({
      limit: "50",
      sort: "-updatedAt",
      filter: "priority <= 2",
      fields: "title,priority",
    });
    if (cursor) query.set("cursor", cursor);

    const page = await trestle(
      `/api/v1/collections/issues/records?${query}`,
    );
    yield page.items;
    cursor = page.nextCursor;
  } while (cursor);
}

for await (const issues of issuePages()) {
  renderIssues(issues);
}

Use URLSearchParams rather than building query strings by hand. An empty nextCursor means the final page has been reached. Cursor values are opaque and should only be returned to Trestle.

Provider storage

Record semantics are provider-neutral: stable IDs, positive versions, timestamps, optimistic concurrency, defaults and projections behave identically on SQLite and the PostgreSQL provider. Boolean and numeric values are stored using each engine's native types; the API envelope never changes. Concurrent updates with the same version yield exactly one winner and one 412 version_conflict on both providers.
