Operations

Run as a system service

Manage Trestle as a per-OS-user systemd service with trestle service, or use a dedicated-account system-wide unit as an advanced alternative.

Per-user service (supported)

Run Trestle in the foreground with trestle or trestle serve. To keep it running without a terminal, install a per-user systemd unit:

trestle service install                 # optional --listen, --data-dir, --env-file
trestle service start
trestle service stop
trestle service restart
trestle service status
trestle service logs
trestle service logs --follow
trestle service uninstall

The user unit is written to ~/.config/systemd/user/trestle.service and managed with systemctl --user and journalctl --user-unit trestle.service. status reports enabled/running state, PID, version, listen address and a live health check of the public GET /system/health endpoint, and exits nonzero when the service is failed or missing. Uninstall preserves Trestle data and configuration.

service install refuses empty, relative or transient executable paths, writes the unit atomically with a versioned integrity header, and never overwrites or removes a foreign or hand-modified unit. It records --listen and --data-dir (default ./data made absolute, created owner-only). Because a user service does not inherit your shell environment, provide the remaining TRESTLE_* configuration (PostgreSQL TRESTLE_DATABASE_URL, S3/AWS credentials, trusted proxies, timeouts) through a protected environment file:

install -m 0600 /dev/null /absolute/protected/trestle.env
# edit with: TRESTLE_LISTEN=127.0.0.1:8090, TRESTLE_DATABASE_URL=..., TRESTLE_S3_*=...
trestle service install --env-file /absolute/protected/trestle.env

The environment file must be an absolute, regular, non-symlink file with exactly 0600 permissions, owned by the invoking user. Secret values are never copied into the unit or printed. The recorded environment file is revalidated before start, restart and status; stop, logs and uninstall remain available even if it is missing. Changing the file takes effect on trestle service restart.

The generated unit applies baseline hardening: UMask=0077, NoNewPrivileges, PrivateTmp, ProtectSystem=strict, ProtectHome=read-only and ReadWritePaths scoped to the data directory. Repeated installs preserve the installed listen, data directory and environment file unless a flag is given explicitly. System-wide mode (trestle service install --system) is a documented follow-up and is not yet supported.

Advanced: dedicated-account system-wide unit

For a machine-wide deployment, create a dedicated unprivileged account, place an owner-only environment file and run the unit below as an alternative to the per-user service. Keep it explicit and maintain it yourself.

[Unit]
Description=Trestle
After=network-online.target

[Service]
User=trestle
Group=trestle
EnvironmentFile=/etc/trestle/trestle.env
ExecStart=/usr/local/bin/trestle --listen 127.0.0.1:8090 --data-dir /var/lib/trestle
Restart=on-failure
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/var/lib/trestle

[Install]
WantedBy=multi-user.target
TRESTLE_LISTEN=127.0.0.1:8090
TRESTLE_DATA_DIR=/var/lib/trestle
TRESTLE_TRUSTED_PROXIES=127.0.0.1/32

Make the environment file mode 0600 and the data directory mode 0700 and owned by the service account. Trestle normalizes its data-directory permissions at startup, but the service manager and parent directories remain operator responsibilities.

Shutdown

SIGTERM marks readiness false, stops background workers and drains HTTP work within the configured shutdown timeout.
