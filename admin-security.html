Administrator session security

Trestle stores random session tokens as SHA-256 hashes, uses strict HTTP-only cookies and requires a per-session CSRF token for logout and future state changes.

Password storage

Passwords require at least 7 Unicode characters and use Argon2id with a random 16-byte salt, 64 MiB memory, three iterations and two lanes. Encoded parameters are bounded before verification to prevent attacker-controlled resource escalation.

Session contract

  • Random 256-bit bearer token, stored only as a hash.
  • 12-hour absolute expiry, revocation checked server-side.
  • HttpOnly, SameSite=Strict, path-wide cookie.
  • Secure when the direct request is TLS.
  • Origin and CSRF token enforcement for state changes.

Login behavior

Unknown email, wrong password and disabled account return the same generic error. Failed attempts are bounded per direct client address. Successful authentication clears that address's failure bucket.

Current boundary

Password recovery, multiple administrators, personal tokens and proxy-aware secure cookies belong to later checkpoints.

Trestle is being built in the open.
