CP06 · Implemented

Schema changes

Collection metadata and its physical SQLite table now change in the same transaction.

Stable internal identity

Collection tables and field columns derive from random internal IDs, never collection or field names. Renaming a field while retaining its ID therefore preserves its column and data.

Rebuild sequence

  1. Create a temporary strict table with the requested schema.
  2. Copy metadata columns and fields whose stable IDs remain present.
  3. Let SQLite validate required, type, uniqueness and JSON constraints.
  4. Drop the old table and atomically rename the validated replacement.
  5. Commit metadata and physical schema together.

Destructive acknowledgement

Removing a field, changing its type, or making it required returns 409 schema_acknowledgement_required unless the administrator repeats the request with X-Trestle-Acknowledge-Schema: true. Incompatible existing data still rejects the acknowledged change and rolls everything back.

Trestle is being built in the open.
