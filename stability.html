Stable v0.1.1 public preview

Know exactly what v0.1.1 supports.

CP23 and the PostgreSQL parity campaign closed Trestle's planned implementation and hardening programme. The result is the stable v0.1.1 public-preview release (the v0.1.x support contract first established by v0.1.0): all six checksums verify, build provenance is recorded, and the unversioned install and download commands select it.

Supported surfaces

  • Linux and macOS on amd64 and arm64, plus Windows on amd64 and arm64.
  • One Trestle process using an owned local SQLite database or PostgreSQL 16, 17 or 18.
  • Versioned HTTP contracts under /api/v1, /admin/v1 and /system.
  • Application users, scoped service identities, access rules, records, files, SSE, jobs, audit, webhooks, Lambda targets, backups and offline restore.
  • Cross-provider migration between SQLite and PostgreSQL, with provider-specific backup and restore procedures.
  • Checksum-verified archives, user installation, executable update and explicit rollback.

Outside the v0.1.x contract

  • Multiple Trestle processes sharing one database or SQLite on a shared/network filesystem.
  • Managed/serverless PostgreSQL topologies beyond the tested single-process ownership model.
  • Automatic database downgrade during executable rollback.
  • Direct application-user file delivery through collection rules.
  • Target-aware relation foreign keys or automatic relation expansion.
  • Outbound verification email and self-service password recovery.
  • An official container image or managed service.

Release verification

v0.1.1 was released from reviewed commit 745fd0a (release workflow run 33482843753: six archives plus SHA256SUMS, checksum and provenance verification, stable-public-preview body) and passed the permanent read-only release-verification workflow (33483410282: exact seven-asset set, every checksum, constrained gh attestation verify on every archive, body wording). v0.1.0 established the initial contract and was verified through its own release and read-only verification runs.

The PostgreSQL readiness contract is machine-readable at docs/postgres/postgres-readiness.json in the application repository and enforced by TestPostgresReadinessContract, which also probes a real server when configured. One command runs the reproducible PostgreSQL gate against a real server:

./scripts/test-postgres-gate.sh

The gate provisions a disposable local instance when no TRESTLE_TEST_POSTGRES_URL is supplied, never prints connection credentials, and runs the contract probe, the full provider-parameterized suite and the race-enabled provider suite. The PostgreSQL contract and the pre-release position are recorded per checkpoint in PREVIEW-CHECKPOINTS.md; automated, simulated, local real-service and CI evidence are labelled accurately.

Public-preview boundary

v0.1.0 established the initial public compatibility contract; v0.1.1 is the current patch release on the same contract. This is a public preview, not a production or battle-proven claim: native macOS/Windows execution is not yet performed, and a documented breaking correction remains possible before the contract matures.

Trestle is being built in the open.
