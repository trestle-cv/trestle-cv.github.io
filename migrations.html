Database migrations

Numbered application migrations run before the service becomes ready and record their name and UTC application time.

Atomic upgrades

Each current migration executes in a transaction. A failed statement rolls the migration back, leaves the schema version unchanged, closes the database, and prevents the server from listening.

Version behavior

A fresh database applies every migration in order. Restarting an up-to-date database is a no-op. A database with a schema version newer than the executable is rejected rather than guessed at.

Current schema

Version 1 reserves Trestle-owned tables for migration history, system metadata and future audit facts. User collection names will be prevented from colliding with the reserved namespace.

Upgrade caution

Supported release upgrade and rollback procedures do not exist yet. Do not treat the development schema as stable.

Trestle is being built in the open.
